# 现场实时打分平台 (Live Scoring Platform)

一个为现场评审 / 演出 / 比赛设计的实时打分系统。在同一局域网下，用一台电脑投影**大屏**、手机**扫码打分**、管理员在**后台**配置、**手机控制台**切页，所有数据实时同步。

> 技术栈：Node.js · Express · WebSocket (`ws`) · SQLite (`better-sqlite3`) · `qrcode` · `docx`

---

## ✨ 功能特性

- **四端协同，实时同步**
  - 🖥️ **大屏显示** (`/screen`)：投影端，支持 4 个页面切换 —— 纯背景 / 选手资料 / 打分页 / 排行榜。
  - ⚙️ **管理后台** (`/admin`)：添加选手（名字 + 图片）、评委（名字 + 图片 + 密码 + 专业/大众类型），配置评分规则与背景图。
  - 📱 **评委打分** (`/judge`)：手机扫码进入，数字键盘打分，支持「一人一码」专属直登。
  - 📱 **手机控制台** (`/control`)：扫码进入，切换大屏页面、选择当前选手、开始 / 结束评分、查看评委打分进度。
- **双轨评分**：专业评委分 + 大众评委分，按权重（默认专业 70%）合成最终得分；大众评分默认**关闭**，可在后台开启。
- **评分规则**
  - 大众评分后台开关（默认关）。
  - 可设置「去掉一个最高分和一个最低分」（专业 / 大众分别去极值，≥ 3 人时生效）。
  - 只展示已提交分数的评委；未提交的评委（即便已结束）不显示、也不计入。
- **一人一码**：每位评委生成专属二维码，扫码后只显示自己的账号，避免输错。
- **二维码批量导出**：一键导出 Word（A4 每页 9 宫格），每个二维码下方标注评委名称 + 密码，方便打印分发。
- **重置评分数据**：保留选手与评委名单，仅清空分数并复位评分状态。
- **数据持久化**：所有配置与分数存于 SQLite（`data/pingfen.db`），重启不丢。

## 📦 安装与运行

要求 **Node.js ≥ 16**（依赖 `better-sqlite3` 原生模块）。

```bash
git clone <your-repo-url>
cd pingfen
npm install
npm start
```

启动后控制台会打印当前局域网地址，例如：

```
http://192.168.1.12:3000
```

在**同一 Wi-Fi / 局域网**下，用不同设备打开对应页面：

| 页面 | 地址 | 用途 |
| --- | --- | --- |
| 首页导航 | `http://<IP>:3000/` | 四个入口总览 |
| 大屏投影 | `http://<IP>:3000/screen` | 接投影仪 |
| 管理后台 | `http://<IP>:3000/admin` | 电脑端配置 |
| 评委打分 | `http://<IP>:3000/judge` | 手机扫码 |
| 手机控制台 | `http://<IP>:3000/control` | 手机扫码切页 |

> 手机扫码的二维码地址由后台根据当前局域网 IP 自动生成。如果更换网络（例如改用手机热点），请重启服务以重新识别地址，必要时重新导出评委二维码 Word。

## ⚙️ 环境变量

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `PORT` | `3000` | 服务监听端口。 |
| `LAN_IP` | 自动检测 | 手动指定对外地址（优先级最高）。当自动识别到虚拟网卡 / 链路本地地址时可用此项覆盖。 |
| `HOST` | 自动检测 | 次优先级的地址覆盖项。 |

示例：

```bash
PORT=8080 LAN_IP=192.168.0.10 npm start
```

## 🚀 使用流程

1. **后台配置**：在 `/admin` 添加选手（名字 + 头像）和评委（名字 + 头像 + 密码 + 类型）。
2. **导出二维码**：在后台导出「评委二维码 Word」，打印分发给评委；或让评委直接扫大屏 / 后台展示的通用码。
3. **控制台准备**：手机打开 `/control`，选择当前选手，切换到「选手资料」页，点「开始评分」。
4. **评委打分**：评委扫码 → 选名字 / 输密码登录（专属码自动登录）→ 数字键盘输入分数 → 提交。
5. **结束与排行**：控制台点「结束评分」，切到「排行榜」页查看最终排名。

## 🌐 部署到 Render（Node.js + SQLite，免费版）

适合校内 / 小流量现场。免费实例长时间无访问会休眠，有人访问时自动唤醒（首次唤醒约 10–30 秒）。

### 前置改动（本项目已包含）

- 服务已绑定 `0.0.0.0`，可直接对外。
- 二维码 / 分享链接地址通过环境变量 **`BASE_URL`** 指定，部署后扫码才能指向公网域名。
- `playwright` 已移至 `devDependencies`，避免部署时下载 Chromium。

### 步骤

1. 把代码推到 GitHub（已含 `README.md` / `.gitignore`）。
2. 打开 [render.com](https://render.com) → **New + → Web Service** → 关联你的 GitHub 仓库。
3. 配置：
   - **Build Command**：`npm install --omit=dev`（只装运行依赖，不装 playwright）
   - **Start Command**：`node server.js`
   - **Instance Type**：Free
4. **Environment Variables** 添加：
   - `PORT` = `10000`（Render 默认，服务已读 `process.env.PORT`）
   - `BASE_URL` = `https://<你的服务名>.onrender.com`（**务必填**，否则评委二维码指向内网地址无法访问）
5. 点 **Create Web Service**，等部署完成。打开分配的 `*.onrender.com` 域名即可使用。

### 注意事项

- **数据库持久化**：免费版文件系统为临时盘，每次重新部署会重置 `data/pingfen.db`。比赛当天部署、当天使用通常没问题；若需跨部署保留名单与分数，建议升级到付费实例（持久磁盘），或定期备份 `data/pingfen.db` 后恢复。
- **休眠唤醒**：首访可能稍慢（冷启动），评委扫码前先打开一次大屏页预热。
- **原生模块**：`better-sqlite3` 会在 Render 构建时编译，构建环境已具备工具链，正常通过。

## 🟢 部署到 Replit（Node + SQLite，开箱即用）

Replit 原生支持 Node.js 与持久化文件系统，SQLite 数据在休眠 / 唤醒后**不会丢失**（详见下方说明），适合教学演示与小项目。

### 步骤

1. 打开 [replit.com](https://replit.com) → **Create Repl → Import from GitHub**，选择你的仓库（或新建 Node Repl 后粘贴代码）。
2. **Packages** 里确认依赖安装完成（`npm install` 会在 Replit 构建时自动执行；`better-sqlite3` 原生模块可正常编译）。
3. **Run** 配置：Entry point 设为 `server.js`（或 Build/Run 命令 `node server.js`）。
4. Replit 会自动注入 `REPLIT_DOMAINS` 环境变量，本项目据此生成公网地址，**评委二维码无需手动配置即可指向 `*.replit.app` 域名**（也可在 Secrets 里手动设 `BASE_URL` 覆盖）。
5. 点 **Run**，右侧预览 / 分配的 `*.replit.app` 域名即可访问；手机扫码用该域名。

### 关于 SQLite 数据是否会被清空

**结论：Replit 的休眠（sleep）不会导致 SQLite 数据被清空。**

原因与对比：

| 场景 | Render（免费 Web Service） | Replit（免费 Repl） |
| --- | --- | --- |
| 进程休眠 / 唤醒 | 文件系统持久，但**重新部署**会重置磁盘 | 工作区文件系统**持久**，休眠不影响文件 |
| SQLite 数据在休眠后 | 仍保留（休眠≠重置） | **仍保留** |
| SQLite 数据在重新部署后 | **免费版会被清空**（临时盘） | 重新部署通常**保留**（持久盘） |
| 数据真正丢失的情况 | 重新部署、删除服务 | 删除 Repl、长期不活跃被回收、手动 Reset |

> Replit 的工作区文件保存在持久卷上，进程停止 / 休眠只是把容器挂起，磁盘上的 `data/pingfen.db` 一直都在，下次启动照常读取。本项目用 WAL 模式，即使休眠瞬间正好在写入，重新打开时 SQLite 也会自动回滚 / 检查点恢复，不会损坏。

### 注意事项

- 免费版同样有**休眠**：长时间无访问会暂停，下次访问自动唤醒（首访约几秒到十几秒）。
- **备份习惯**：虽然持久，重大活动前仍建议下载备份 `data/pingfen.db`（在 Replit 文件面板右键下载），以防误删或回收。
- 端口：Replit 会注入 `PORT`，本项目已读取；绑定 `0.0.0.0`，直接对外。

## 🔌 主要 API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/state` | 获取当前完整状态 |
| `GET` | `/api/info` | 返回局域网 IP / 端口 / 基础地址 |
| `POST` | `/api/judge/login` | 评委登录（名字 + 密码） |
| `POST` | `/api/upload` | 上传头像 / 背景图（base64） |
| `GET` | `/api/qrcode/judge?j=<ID>` | 评委二维码（带 `j` 为专属码） |
| `GET` | `/api/qrcode/control` | 手机控制台二维码 |
| `GET` | `/api/export/judge-qrcodes` | 导出评委二维码 Word（A4 每页 9 个） |

状态同步通过 WebSocket（`/ws`）广播，前端用 `connectState()` 订阅。

## 📝 说明与建议

- **安全性**：本平台面向受信任的局域网现场环境，后台与评委登录未做高强度鉴权。若通过手机热点等开放网络发布，建议为后台增加访问口令。
- **部署到公网**：当前按局域网设计。如需公网访问，请配合反向代理（Nginx/Caddy）并启用 HTTPS，同时注意评委密码等数据的传输安全。
- **数据备份**：`data/pingfen.db` 为唯一数据源，建议定期备份该文件。

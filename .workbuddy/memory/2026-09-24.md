## 现场实时打分平台（pingfen）
- 在 D:/treaWork/pingfen 搭建了一个 Node 实时打分 Web 平台。
- 技术栈：Express + ws(WebSocket) + qrcode，纯前端 vanilla JS，无构建步骤。
- 四个端：大屏 `/screen`、管理后台 `/admin`、评委扫码 `/judge`、手机控制切页 `/control`，首页 `/` 为导航 hub。
- 实时同步：所有端通过 `/ws` 接收全量 state 广播；评委提交分数走 `submitScore`，管理员/控制端发 `setPage/setScoring/setBackground/addContestant...`。
- 图片（背景/头像）由前端读成 base64，`POST /api/upload` 存到 `public/uploads/` 返回 URL。
- 二维码：`/api/qrcode/judge`、`/api/qrcode/control` 由服务端用局域网 IP 生成。
- 坑：① npm 官方源 502，改用 `registry.npmmirror.com` 镜像安装成功；② `os.networkInterfaces` 会先返回 VMware 的 169.254 链路本地地址，已加过滤（跳过 169.254 / 虚拟网卡，优先 WLAN）；可用 env `LAN_IP` 手动覆盖；③ express.static 需加 `extensions:['html']` 才能用 `/screen` 这种无扩展名路径。
- 启动：`cd D:/treaWork/pingfen && node server.js`（默认端口 3000，PORT 可改）。已在本机 10.56.128.232:3000 跑通冒烟测试。

## 第二轮升级（按用户示意图）
- 新增：评委管理（名字+头像+密码+专业/大众类型）、评委登录接口 `POST /api/judge/login`、控制台选选手（currentContestantId）、专业/大众双轨打分与加权最终得分（proWeight 默认 0.7，可后台改）、大屏"当前选手+三分数+评委分数墙"打分页、评委端数字键盘打分 UI、选手 desc 字段。
- **坑1（重要）**：JS 对象字面量写重复的 `type` 键（`{type:'addJudge', ..., type:'pro'}`）后者静默覆盖前者，导致消息 type 变成 'pro' 走进 default 分支，且不报错。排查手段：服务端 handleMessage 入口加 console.log 打印收到的 msg。
- **坑2（设计教训）**：消息派发键和业务字段不能共用同一个名字——`msg.type` 既做 WS 派发又当评委类型，大众评委永远设不上。已改用独立 `role` 字段（pro/mass），分数记录里是 `judgeType`。
- **坑3**：Windows 上两个 node 进程可同时绑定 3000 端口（netstat 可见两个 LISTENING），导致 WS 消息进新进程、HTTP 读旧进程的"灵异"现象。用 `taskkill //F //PID xxx` 全部杀掉再重启。
- E2E 已验证：错误密码 401、登录成功返回 role、双轨打分记录 judgeType、最终得分 = 0.7×95+0.3×88=92.90。
